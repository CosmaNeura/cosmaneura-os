# Membership/Billing coworker

Practice Manager v2 connects its Membership/Billing coworker to the existing
private membership and payment workflows. Add the group in team settings, or use
the explicit upgrade for an existing v1 group. Rehearse and review the change
before saving. The upgrade preserves coworker identity, preferences and restrictions.

In the encounter conversation, select the Membership/Billing coworker. Choose
Membership or Payment requests, then a saved work record. Review the selected
evidence and consent to one AI review. The answer explains the record's status,
reconciliation gaps and human next steps. Open Work to prepare enrollment assistance,
membership status review, failed-payment follow-up or a reviewed payment request.
Payment lists support the existing pagination contract.

The selected model input contains only the displayed work facts, human review
notes, ledger observation fields where present, and the fixed review question.
Notebook, conversation history, bot preferences, patient identifiers, account labels,
vendor identifiers and document references are excluded. Owner-entered review notes
are untrusted evidence. Manual ledger claims, processor observations and human
verification remain distinct; payment does not establish membership.

The request records the exact work version, review and evidence commitment.
Admission, dispatch and result disclosure recheck current private scope, work and
connection authority. A source or authority change withholds stale output.
An uncertain request retains its original selection, consent and request key in
the encrypted journal. Starting another attempt requires a fresh evidence review
and fresh consent; the prior request remains recoverable.

An answer does not send reminders, change enrollment, create charges or refunds,
record payments, close work, or initiate a handoff. These remain separate human
workflows. No live membership service is implied by a local ledger review.

Team/catalog contract4 is required for this skill; identity/activity remain on
their existing contract2. Prior configurations and requests retain their original
representation. The OS schema is unchanged. Web, Mac and iPhone share the same
source selection/recovery implementation. Actual account and device acceptance
still requires the configured beta environment.
