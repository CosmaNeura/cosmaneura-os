# Operational agent source delivery

Ordinary operational admissions use `cosmas-gpt41-prepared.v6`. The existing v1–v4
text decoders and v5 tool envelope remain supported for their saved requests.
The v5 body, selection, output schema, tool definitions and receipt validation
are unchanged. A v6 body cannot be replayed under a v5 contract.

The v6 admission commits the full original selected context and source hashes.
The stored v4 baseline is an exact derived bounded preparation used for output
schema compatibility; it is not the source of current-input authority. Claim,
each tool read and settlement recheck the full original context. A changed tail
or a source omitted from initial delivery still invalidates the admission.
JSONB descriptor ordering is reconstructed only through the existing exact v4
record-order validator; the saved provider string, schema and body stay pinned.

Ordinary long sources initially deliver up to 1,000 characters per source and
6,000 characters total. An explicit manifest separates full original hashes
from excerpt lengths/hashes and identifies omitted sources. The source handles
are already supplied, so an extra listing round is unnecessary. Complete short
source sets use the original full-body path with a brief instruction to avoid
redundant reads. Reviewed Scribe transcript/summary packets remain indivisible:
all their parts must fit the existing complete-context bounds and are delivered
in full, even when they exceed the ordinary compact budget.

An exact `read_selected_source` response must match the original entry,
revision, content hash, label, kind and text, with no additional data fields.
The shared transport also checks its dispatch, admission, actor, human,
workspace, request, selection, result and envelope receipt commitments. After
that check, later requests remove only that source's initial excerpt; the
receipt-bearing full result supplies its text once.

The v6 output decoder permits citations and Scribe verbatim quotes only from
actually delivered initial text or a successfully verified exact source read.
A handle, saved baseline tail, teammate draft or operation receipt does not
make an unseen clinical source citable. A successful full read can support a
tail quote or an initially omitted source, within the original selected scope.
The strict output schema, handoff target/role requirements, source tense,
unknowns, clinician review and existing single-dispatch recovery remain in
force. Tool reads grant no external action or new approval authority.

Qualification uses invented sources and fake upstream HTTP with the actual
adapter, PostgreSQL admission, scoped tool reader and settlement. Report wire
bytes separately from verified provider tokens. Scripted response rounds do
not establish actual model quality, latency, cost or public-launch readiness.

Research admissions with current reviewed connector authority use v7. A new
v8 envelope adds `execute_reviewed_delivery` and `read_delivery_status` only
for an explicit Follow up conversation with a current approved administrative
Spruce message. Private specialist handoffs remain drafts. Saved v6 and v7
envelopes replay through their original validators and definitions.

The human approval names the current Follow up bot and commits the unchanged
recipient, message, reviewed note, revision and operation. Each tool and the
provider runtime recheck that approval, current team, signed identity and source.
The model receives four handles; it cannot supply a destination, attachment or
replacement message. Runtime unavailability does not spend a submit claim.
Once the existing connector claims an operation, reconnection reads retained
receipts and never submits it again, including when the outcome is uncertain.
Provider acceptance remains separate from observed transport, patient receipt
and clinical completion. The local completed-action lab adds an independent
receiver receipt and a later virtual-patient acknowledgment to qualify its
own sandbox outcome.
